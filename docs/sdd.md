# SDD · первая заявка стажёра Alpha

## Общее поведение

Вход агента - сообщение стажёра и состояние сценария из хранилища. Идентификатор, роль и команда приходят от серверной аутентификации. Пользователи Alpha и Beta используют разные тестовые учётки. Доступ к ресурсу `team_space` разрешён роли `intern` команды Alpha.

| Намерение | Поведение |
|---|---|
| explain_access | Вернуть доступную инструкцию Alpha с идентификатором источника |
| request_access | Показать форму причины или создать/вернуть текущий черновик при известной причине |
| request_status | Вернуть текущий сохранённый статус и номер заявки, если получен |
| next_step | Вернуть рекомендуемое действие из текущего состояния |
| clarify | Попросить уточнить задачу. Одиночное «да» не отправляет заявку |
| out_of_scope | Вернуть границы демо и направить к наставнику |

Встроенный классификатор учится только на train. Для Qwen3-1.7B используется локальный адаптер Артемия и строгий контракт HTTP. Оба варианта возвращают только намерение. Состояние передаётся сервером, а разрешения и правила операций проверяются независимо от ответа модели.

## Инструменты

- `ask` принимает сообщение до 500 символов. Показывает инструкцию, состояние или предложение заполнить причину для черновика. При сбое маршрутизатора возвращает ошибку без записи заявки.
- `prepare_draft` принимает причину (1–400 символов). Возвращает сохранённый черновик и URL. Текущий черновик повторно используется для одного стажёра и ресурса.
- `request_status` читает текущий черновик. До создания возвращает `not_started`.
- Подтверждение доступно через авторизованную страницу `/drafts/{id}`. Принимает ID и версию. Сервер проверяет владельца и права и вызывает имитацию корпоративного сервиса. Сервис генерирует номер, возвращает `pending_approval`, бэк сохраняет оба значения. Повторный вызов возвращает тот же результат.

## Проверки до приёмки

1. Инструкция доступна Alpha, защищена от выдачи Beta.
2. Вопрос, подготовка, явное подтверждение и повторное чтение приводят к одному номеру заявки в веб-интерфейсе/API и MCP.
3. Чужой черновик и устаревшая версия не меняют состояние. Текст «да» и неизвестные команды не отправляют заявку.
4. Повтор и конкурентные подтверждения оставляют одну заявку. При сбое сервиса интерфейс показывает ошибку. Повтор безопасен.
5. После обновления страницы и перезапуска сохранённая заявка читается из БД.

Идентификатор операции имитации - ID черновика. Один пользователь ведёт одну заявку на ресурс в пределах демо. Соединение с настоящим корпоративным API требует отдельной сверки результатов по ключу операции.
