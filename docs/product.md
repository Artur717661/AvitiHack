# Продукт и внедрение

## Почему этот сценарий

В первую неделю [чек-лист Авито](https://docs.google.com/spreadsheets/d/1qKFqOzfSZ2jEz57jBSmq7rukDXi_tRfWohgemViceV0/edit?usp=sharing) предлагает познакомиться с командой, подключиться к чатам и запросить доступ к пространству. Во вторую неделю - изучить командные материалы и зафиксировать цели адаптации. На вкладке Backend в первую неделю идут настройка инструмента, ключи и учебные задачи, во вторую - документация по данным, платформе и Go.

Командная вики находится на стыке этих недель. Без неё стажёр может застрять на поиске порядка действий и обращаться к наставнику за инструкцией и повторной проверкой статуса. Для демо довели один сценарий от первого вопроса до записи заявки. Вики Alpha, пользователи, инструкция и согласование синтетические.

## Как устроено решение

| Компонент | В прототипе | Для пилота |
|---|---|---|
| Авторизация | Тестовые учётки, подписанная cookie, тестовый токен MCP | Корпоративный SSO, отдельная идентификация вызывающего пользователя в MCP, каталог сотрудников |
| Роли | Команда/роль из тестового каталога, проверка владельца черновика | Запрос прав к корпоративному API для каждого чтения и записи |
| Знания | Версионированные файлы Alpha, ответы с источником | Подключить разрешённые разделы базы знаний и обновление версий |
| Определение намерения | Лёгкий локальный классификатор и отдельный HTTP-режим Qwen + LoRA | Подключить внутренний агентный сервис по тому же контракту, измерить ошибки на новых запросах |
| Данные | PostgreSQL; SQLite для запуска без сервисов | PostgreSQL с миграциями и журналом операций. Redis нужен, если понадобятся общий кеш или распределённые сессии |
| Заявки | Имитация реестра и сохранение результата в транзакции | Реальный API заявок с ключом операции, сверкой исхода после таймаута и аудитом |
| Интерфейс | React, TypeScript, Zod и явный клиент API; чат и страница в одном приложении | Сохранить HTTP-контракт при подключении корпоративной оболочки. TanStack Query и Zustand полезны при росте количества экранов и общего состояния |

В браузере сессия защищена подписью, cookie HttpOnly и SameSite=Strict. Сервер принимает записи с согласованного адреса и проверяет владельца, команду и версию. На странице статуса запросы читают сохранённые данные. Модель не получает идентификатор стажёра в промпте и не выбирает объект доступа. Сбой имитации откатывает обе записи. При внедрении настоящий сервис будет за пределами транзакции, поэтому понадобится отдельная сверка операции.

## Как проверить пользу

Пилот на тестовых учётках с участием 30–40 согласившихся стажёров. Случайно распределить участников внутри команд между обычной инструкцией и AI-buddy. Дать одинаковую задачу доступа к одной тестовой вики и одинаковую возможность обратиться к наставнику. Запустить пилот в первую неделю, результаты сравнить после второй.

| Метрика | Что измерить | Ориентир пилота |
|---|---|---|
| Время до подачи | Медиана времени от задания до записи заявки | На 20% ниже |
| Нагрузка наставника | Число запросов о доступе и его статусе на стажёра | На 25% ниже |
| Завершение без подсказки | Доля стажёров, самостоятельно подавших заявку | Выше контрольной группы |
| Первая самостоятельная задача | Дни от выхода на стажировку до принятия первой задачи по критериям наставника | Отслеживать как итоговый эффект адаптации |
| Ошибочная отправка | Неверный ресурс, дубль или отправка без подтверждения | Ноль в проверенных случаях |
| Отзывчивость | p95 открытия черновика и время до отображения ожидания | Локальная операция < 1 с |

Отмечать события начала задачи, показа инструкции, создания черновика, подтверждения, результата, сбоя и обращения к наставнику. Для пилота достаточно псевдонима, времени и кода события. Текст сообщений и причин не нужен для расчёта. Указанные проценты - критерии пилота. Измерений на стажёрах пока нет.
